# تقرير تدقيق شامل — موقع أحمد حداد (Rate Card + Equipment + Admin)

> تقرير فقط — لا تعديلات حتى موافقتك. اختر بعده أي محور نبدأ به.

## 1. الملخص التنفيذي

- **طبيعة المنتج:** موقع Portfolio + Rate Card ثنائي المنطقة (عمّان/إربد) + معرض معدات + لوحة إدارة مع تسعير AI.
- **الوضع الحالي:** يعمل ويقدّم القيمة الأساسية (عرض الأسعار). حصلت مؤخراً على تحسينات أمنية + معالجة أخطاء (B3–B9) + منطق مناطق سليم.
- **أهم 5 مخاطر:**
  1. الصفحة الرئيسية `iframe` يحمّل `ratecard.html` ثابت → SEO/OG/Deep-link/Analytics = صفر.
  2. الأسعار وبيانات الخدمات مكتوبة يدوياً داخل HTML (1460 سطراً) → صيانة هشّة وخطر تناقض مع صفحات أخرى.
  3. لا يوجد CTA تحويلي حقيقي (واتساب / نموذج طلب عرض) → الموقع يعرض ولا يحوّل.
  4. لا يوجد Portfolio/Showreel/شهادات عملاء → غياب دليل اجتماعي في مجال بصري.
  5. جاهزية الهاتف كتطبيق = منخفضة (منطق مدمج بـ DOM/inline styles، لا نظام تصميم، لا API طبقة مستقلة).
- **قرار الجاهزية للنشر الحالي:** **جاهز بشروط** — يمكن الاستمرار في الإنتاج كـ Rate Card، لكن قبل حملة تسويق فعلية لازم CTA + هيكلة SEO.
- **قرار الجاهزية للتحويل إلى موبايل:** **يتطلب إعادة هيكلة متوسطة** قبل التفكير بأي wrapper/native.

---

## 2. فهم المنتج والسياق

- **المستخدم:** عميل محتمل في الأردن (طالب، شركة، منظّم إيفنت، وكالة) يريد معرفة سعر خدمة تصوير في عمّان أو إربد.
- **المهمة الأساسية:** اختيار المنطقة → اختيار الخدمة → رؤية السعر → **التواصل** (هذه الخطوة الأخيرة غائبة عملياً).
- **الرحلات الفرعية:** تصفح المعدات، والإدارة الداخلية (Admin + AI تسعير معدات).

## 3. نتائج التدقيق حسب المحاور

### 3.1 UX / UI

| # | المشكلة | الأثر | الشدة |

| UX-2 | اختيار المنطقة يحدث مرة ولا يمكن تغييره بسهولة/غير واضح مكان الإعادة | ارتباك زوار عمّان بعد المشاركة | عالٍ |

| UX-4 | نصوص السعر الإنكليزية والعربية أحياناً غير متطابقة (`price-note`, `price-unit`) بعد التعديلات اليدوية الأخيرة | يكسر الثقة | عالٍ |
| UX-5 | لا حالة Empty/Loading احترافية في `equipment` (نص فقط) | تجربة أدنى من مستوى الهوية | منخفض |

| UX-8 | صور المعدات على خلفية بيضاء داخل ثيم أسود → قاسية بصرياً | جودة الانطباع | منخفض |

### 3.4 المنطق الوظيفي

| # | المشكلة | الشدة |
|---|---|---|
| L-1 | أسعار hardcoded في `ratecard.html` → أي تعديل مستقبلي = خطر Regression (شاهدنا هذا فعلاً في الجلسات السابقة) | حرج |
| L-2 | `rowRegion()` يعتمد كلمات مفتاحية عربية/إنكليزية داخل النصوص — أي تعديل نص يخرب التصنيف | عالٍ |

| L-4 | `estimateEquipmentPrice` بدون تحقق أن المستخدم Admin (فقط auth) → أي مستخدم مسجّل يستهلك AI credits | عالٍ (تكلفة) |

| L-6 | لا Audit Log لتغييرات المعدات (من عدّل، متى، ماذا) | متوسط |
| L-7 | Delete بدون Soft-delete → فقد بيانات نهائي | متوسط |
| L-8 | لا Bulk actions (تفعيل/تعطيل، تعديل فئة) | منخفض |

## 4. خارطة الطريق التنفيذية

### المرحلة A — أساسات ما قبل الحملة (1–3 أيام)
1. **A1** تحويل `ratecard.html` من iframe إلى Route React `/` مع URL state (`?region=amman&service=short-film`).
2. **A2** استخراج كل الأسعار إلى ملف JSON واحد `src/data/pricing.ts` — مصدر حقيقة واحد.
3. **A3** إضافة CTA واتساب عائم + زر "احجز الآن" أسفل كل خدمة → رقم مع رسالة مسبقة.
4. **A4** `og:image` (توليد صورة hero) + عنوان/وصف لكل route.

### المرحلة B — Trust & Conversion (3–5 أيام)
5. **B1** صفحة `/portfolio` (شبكة فيديو/صور من Vimeo/YouTube).
6. **B2** صفحة `/about` + `/contact` + `/faq` كـ routes مستقلة.
7. **B3** نموذج "طلب عرض سعر" يحفظ في Supabase + Email للمالك.
8. **B4** شعارات عملاء / تستيمونيالز (حتى لو 3 كبداية).

### المرحلة C — تقوية الإدارة والأمان (2–4 أيام)
9. **C1** نقل Admin تحت `_authenticated/` layout gate.
10. **C2** إضافة role check على `estimateEquipmentPrice` + rate-limit بجدول Supabase.
11. **C3** Audit log + Soft delete + Bulk actions.
12. **C4** Sentry أو ما يعادله + smoke tests بسيطة (Playwright: تحميل الصفحات + تبديل المنطقة + بحث المعدات).

### المرحلة D — الأداء و SEO (2 أيام)
13. **D1** sitemap.xml، robots.txt، Schema.org (`LocalBusiness` + `Service`).
14. **D2** تحسين صور معدات (تخزينها في Supabase Storage + srcset).
15. **D3** Preconnect للخطوط + `font-display: swap`.

### المرحلة E — تجهيز الموبايل (اختيارية، 3–5 أيام)
16. **E1** استخراج design tokens (colors/typography/spacing) إلى `src/styles.css` @theme + إزالة inline styles تدريجياً.
17. **E2** فصل service layer (`src/lib/api/*.ts`) عن الكومبوننتس.
18. **E3** تفعيل PWA (manifest + service worker + offline pricing).
19. **E4** بعد ذلك يمكن دراسة Capacitor wrap أو React Native reuse.
